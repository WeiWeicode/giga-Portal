## 0. 共通原則

### 0.1 架構(沿用 giga-Portal 現有框架)

| 項目 | 做法 |
| --- | --- |
| 登入 / 身分 | Gateway 單一入口;portal-api 只信內部 Token 的工號、部門(含下層)、角色。**不接受**瀏覽器送來的工號、部門、隱藏欄位 |
| 權限 | 選單 / Tab / 按鈕由 BFF 計算;**每支 API 都有權限代碼**,寫入 API 代碼 = 按鈕 `v-can` 代碼;主管 / ESH 資料由後端依 Token 範圍過濾,違反回 403 `PORTAL_DATA_ACCESS_DENIED` |
| 資料 | 舊表以來源前綴 + 參數化查詢(並行期寫入格式與舊系統一致,D-7);入口網新資料放 `portal` schema(Drizzle) |
| TIPTOP 來源 | 系統轉移中(D-1):整頁或欄位顯示「系統轉移中」,不呼叫 OPENQUERY |
| BPM | 唯讀查 NaNa(`portal_bpm_ro`),簽核動作以深連結回 BPM 原畫面(D-6) |
| 檔案 | 一律經 giga-file-service(UUID、副檔名 / 大小白名單);portal-api 不寫網站目錄 |
| 寄信 | 經 Gateway 通知中心 / 公司 SMTP 設定;收件人來自資料或設定,**不寫死個人信箱**;寄送結果記錄 |
| 錯誤 | 查無資料回空清單或 404,不讓例外變成錯誤頁;錯誤訊息含 requestId |

### 0.2 不照抄清單(舊系統的寫法,新系統一律不做)

| 舊寫法 | 新做法 |
| --- | --- |
| 萬用登入密碼、萬用薪資解鎖碼、網址帶帳密登入 | 不存在任何萬用碼;登入只經 Gateway |
| 可逆加密存密碼、明文密碼寄信 / 顯示、密件副本給個人信箱 | 不經手密碼;忘記密碼走 Gateway 重設流程(只寄重設連結) |
| 只隱藏選單、後端不檢查 | 每支 API 驗權限與資料範圍 |
| 寫死工號當管理者(S094009 等)、寫死「860000 看全公司」 | 改角色 / 按鈕權限,由 IT 在 GigaItApp 指派 |
| 工號放在隱藏欄位、ViewState 回填身分 | 身分只取 Token |
| SQL 字串拼接、未編碼輸出 HTML | 參數化;使用者 HTML(公告、問卷說明)以白名單過濾後輸出 |
| 先寫檔 / 先刪後插、無交易 | 驗證完才寫;多步寫入包交易 |
| 寫死年度、期別、範本檔、公司代碼清單 | 設定化(表或環境設定),程式不寫年份 |
| 雙胞胎頁(HRPersonalSalary / HRMPersonalSalary 等) | 一頁一份邏輯,差異用參數 |
| 外部系統以寫死 DES 金鑰或 Base64 工號跳轉 | 不產生任何舊格式 token;頁面只顯示「DES 跳轉(待重構)」(§6.3、D-22) |

## 1. 首頁(`/`,`portal.home.read`)— P3 ⏳

**目的**:登入後一頁看到「今天要處理的事」。以聚合路由 `GET /api/portal/dashboard` 一次取得,單一區塊失敗只該區塊顯示「暫時無法取得」(FR-4.8)。

| 區塊 | 資料與規則 | 舊系統對照 |
| --- | --- | --- |
| 問候 | `/api/auth/me` 的姓名、工號、部門、分機 | 左側身分卡 |
| 待辦事項 | 依序合併(每項附連結):① BPM 待簽核 / 未結案筆數(§2 BPM 查詢)② 未填問卷(§3.4 資格規則)③ 未完成新人導覽 / 驗收(§3.5,只對到職 N 天內者,建議 90 天)④ 待簽同意書與臨時服務(§8)⑤ 個人提醒中今天到期者(§2)。全部沒有時顯示「無重要事項」 | 舊首頁 15 種提醒中:出勤異常、二代健保、勞健保異動、加班費扣款、薪資異動、密碼到期 → 🚧(TIPTOP / AD,不顯示) |
| 個人秘書 | BPM 待簽核數 + 前往 BPM;個人常用連結(`PersonalSystemLink`,本人可新增 / 刪除 / 排序,建議) | 舊「未結案」數字因 bug 從未顯示,新版正確顯示 |
| 最新公告 | Gateway 通知中心(已接)+ 舊 `ContentX` 公告**唯讀併入**,標來源「舊入口網」;舊站下線後移除(D-21) | 舊最新消息跑馬燈 |
| 公告輪播 / 集團動態 | 圖片由編輯者在後台上傳(giga-file-service),依起訖日顯示;不再寫死檔名 | 舊 8 張圖寫死在 aspx |

- 不檢查 IsBoss 之類旗標;首頁內容只依本人資料。
- 舊首頁的寫死年度同意書(2026 禾迅增資)改由 §8 同意書服務依資料產生待辦。

## 6. 共用元件 / 其他

### 6.1 帳號類頁面

登入、註冊、重設密碼只由 Gateway 流程提供(`/login`、`/register`、`/reset-password`,已完成)。舊系統的申請帳號(明文存密碼)、忘記密碼(還原並寄出明文)、EipLogin(可偽造)**全部不沿用**。並行期舊站這些頁面屬舊系統維運,不在 giga-Portal 範圍(D-27),另行通報 IT 下架或修補。

### 6.2 舊系統帳號遷移

Gateway 讀 `LoginData` 做首次登入遷移時,**只用加密欄位驗證後立刻改為 Gateway 雜湊,不讀 `EName`(舊版明文存放確認密碼)**;此規則屬 Gateway,於 Gateway 規格確認(跨 repo,另案)。

### 6.3 外部系統跳轉(訂便當、E-Learning、ERMS、福委會、WebApp、NotesApp、年考核、環安衛資料庫、好書分享、健康系統)

舊站以寫死 DES 金鑰組「加密工號 + 時間」或同步碼跳轉,對方系統依此登入。

**D-22**:過渡期這些項目在入口網**只顯示「DES 跳轉(待重構)」,無任何功能**(不產生 token、不帶連結)。使用者向主管取得各應用原始檔後再分類:

- 小功能(例:訂便當、福委會)→ 日後在 giga-Portal 內重新實作;
- 邏輯較複雜者(例:E-Learning、預約資源)→ 獨立應用,經 Gateway 登入與應用切換。
